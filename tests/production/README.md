# 正式產物旅行手帳驗證

執行 `npm run test:production`，依序建置釜山、輕井澤、東北三套資料，使用測試密碼及測試服務設定，不使用正式服務憑證，也不寫入真實雲端資料。

需要 Playwright Chromium；若使用已安裝的 Chrome，可在 PowerShell 設定 `$env:PRODUCTION_TEST_BROWSER='chrome'`。單一旅程可執行 `npm run test:production -- 2027_tohoku`。`--reuse` 僅供診斷已建置的相同旅程產物；修改程式後須重新建置。

每套旅程驗證 320px 亮色與 390px 深色的以下兩種情境：

- PWA 安裝後清除 HTTP 快取並離線重新啟動，確認未快取的網路請求確實失敗；依序開啟首頁、每日、指南、商店、導遊、記帳，重新選擇並確認明暗主題，展開內容、捲至首次載入的每日地圖，確認地點替代連結可見；恢復網路並重試引擎，以受控背景圖層確認地圖可恢復；再切回離線，確認 AI 失敗提示、記帳立即重新整理後保留、字體從快取載入。
- 阻擋 Service Worker，使用冷快取、200ms 延遲及 256,000 bytes/s 下載速率；字體另延遲 6 秒，確認替代字體期間已可操作，六個分頁均能顯示且沒有橫向溢出或未處理的頁面錯誤。

產物、逐頁截圖與 JSON 結果保存在忽略的 `test-run.local/production-audit`，不覆蓋部署用的 `dist`。只有完整通過的情境才加入結果；全部成功時輸出 12 個通過情境。

外部 API 使用受控失敗回應，地圖使用無效測試金鑰；此處驗證正式產物的離線與載入行為。地圖控制、定位、重試及圖資失敗另由 `tests/e2e/journal-map.spec.js` 驗證，不宣稱真實服務可用。
